# Context

`refer/` 是一个 Next.js + Ant Design 的页面参考实现，包含应用中心、登录页、个人中心，以及它们共用的顶部导航和 mock 数据。`apps/main` 是现有的 Vite + React Router + Zustand + Ant Design qiankun 主应用，目前只有较简陋的登录页、根路由 HostHome，以及 `/apps/mfe-app/*` 子应用挂载路由。目标是把 refer 的三个页面体验迁移到主应用，而不是直接复制 Next.js 文件；同时保留现有认证状态、登录重定向和 qiankun 子应用能力。

> 第一阶段已按本方案完成代码迁移和主应用验证，详细实施契约见 [第一阶段实现计划](./11_IMPLEMENTATION_PHASE_1_PLAN.md)，实际结果见 [第一阶段执行记录](./11_IMPLEMENTATION_PHASE_1_EXECUTION.md)。Host Playwright smoke 已通过；qiankun 远程集成 smoke 需在远程子应用环境就绪后执行。

## 已确认的现状

- 参考页面：
  - `refer/app/login/page.tsx`：左右分栏登录界面、邮箱/密码校验、登录成功提示和跳转 `/`。
  - `refer/app/page.tsx`：应用中心标题、副标题、`AppHeader` 和 `AppGrid`。
  - `refer/app/profile/page.tsx`：头像、用户名、角色标签和用户详情卡片。
  - `refer/components/app-header.tsx`：首页、管理员入口、个人中心、退出登录导航；依赖 `refer/lib/mock.ts` 的用户和子应用 mock 数据。
  - `refer/components/app-grid.tsx`：八个子应用卡片和 Ant Design 图标。
- 主应用：
  - 路由集中在 `apps/main/src/App.tsx`；已有 `/login`、`/`、`/apps/mfe-app/*` 和兜底路由。
  - `apps/main/src/stores/auth.store.ts` 和 `apps/main/src/services/auth.service.ts` 是应继续使用的认证实现，当前用户模型是 `CurrentUser`（`id/name/username/roles/permissions`），与 refer 的 `id/username/role` 不同。
  - `apps/main/src/components/RequireAuth.tsx` 已提供鉴权保护。
  - `apps/main/src/styles/main.css` 目前是现有 shell/login 样式；Tailwind 3 已配置在 `apps/main/tailwind.config.js`。
  - `apps/main/package.json` 有 `antd`，但没有显式声明 `@ant-design/icons`；锁文件中它是 antd 的传递依赖。迁移页面若直接使用 refer 的图标，应将其作为主应用的直接依赖补齐。
  - `/apps/mfe-app/*` 是 qiankun 的保留挂载路径，不能被应用中心页面吞掉。

# 推荐实现

## 路由和页面职责

1. 新增 `apps/main/src/pages/AppsPage.tsx`，承载 refer 的应用中心页面；新增 `apps/main/src/pages/ProfilePage.tsx`，承载个人中心页面。继续使用现有 `apps/main/src/pages/LoginPage.tsx` 文件名，但重做其展示结构。
2. 在 `apps/main/src/App.tsx` 中增加受保护的 `/apps` 和 `/profile` 路由，并把 `/` 作为应用中心入口（渲染同一个 `AppsPage` 或重定向到 `/apps`，统一选择一种实现以避免重复页面）。保留 `/apps/mfe-app/*` 的现有 qiankun 路由，并确保其路由声明不被 `/apps` 的页面路由覆盖。
3. 登录成功后的默认跳转改为应用中心路径；保留 `RequireAuth` 的原始目标重定向逻辑。为了不破坏既有 e2e/使用方式，可让 `/` 继续可访问，并明确 `/apps/mfe-app` 仍用于业务子应用而不是应用中心。
4. 用主应用的 React Router `Link`/`useNavigate` 替换 refer 中的 Next `useRouter`；退出登录必须调用 `useAuthStore.logout()` 后跳转 `/login`，不能只做页面跳转而留下认证状态。

## 组件和数据迁移

1. 新增 `apps/main/src/components/AppHeader.tsx`（或按现有命名风格放入 components），按 refer 实现顶部固定导航、响应式管理员入口、头像下拉菜单。导航使用 `useAuthStore` 的 `user` 和 `logout`，将主应用用户字段映射为显示名、用户名和角色；管理员入口可先复用现有 `/apps/mfe-app` 或新增 `/admin` 占位路由，具体以现有业务路由约束为准。
2. 新增应用中心的数据常量（建议放在 `apps/main/src/data/sub-apps.ts` 或页面附近），迁移 refer 的八个子应用展示字段和图标 key，但不要继续引用 `refer/lib/mock.ts`。卡片点击行为应复用 qiankun 设计：对于尚未接入真实 entry 的卡片，显示 Ant Design message；对已配置的业务应用使用明确的 React Router 路径。默认不伪造远程子应用地址。
3. 新增 `apps/main/src/components/AppGrid.tsx`，迁移 refer 的网格布局、图标映射、hover 状态和移动端网格断点，使用主应用已有的 Ant Design 5 API。
4. `ProfilePage` 使用当前 `useAuthStore().user` 动态展示数据；把 refer 的 `role` 适配为 `user.roles`（例如显示第一个角色或拼接角色），使用 `Avatar`、`Tag`、`Descriptions` 和 refer 的三类字段布局。未登录访问仍由 `RequireAuth` 处理。
5. `LoginPage` 保留现有 `LoginCredentials`、表单提交、错误 Alert、loading、`login()` 和原始目标跳转；只将字段、文案和布局改成 refer 的品牌/视觉风格。由于当前 demo 服务使用 username + password，而 refer 视觉上写邮箱，因此保留 username 作为提交字段并在文案上避免造成“邮箱一定能登录”的误解，或者在产品明确要求邮箱登录后再同步修改认证服务和测试。

## 样式、依赖和清理

1. 在 `apps/main/src/styles/main.css` 中补充参考页需要的背景色、渐变登录布局、顶部导航、页面内容宽度、应用卡片和 profile 响应式样式；优先沿用已有 Tailwind 工具类和 Ant Design reset，不引入 refer 的 Tailwind v4/shadcn 全套配置。
2. 在 `apps/main/package.json` 增加 `@ant-design/icons` 的直接依赖（版本与当前 antd 5 兼容），更新 lockfile；不迁移 Next、`@ant-design/nextjs-registry`、shadcn、`tw-animate-css` 或 Next metadata/provider，因为 Vite 应用不需要它们。
3. 如应用中心不再需要现有 `HostHome`/roadmap 内容，删除或改为兼容入口，避免保留死代码；保留 `MicroAppOutlet` 和其容器、fallback 文案。

# 验证步骤

1. 安装/更新依赖后运行 `pnpm --filter tsuz-web-main lint`、`pnpm --filter tsuz-web-main test` 和 `pnpm --filter tsuz-web-main build`。
2. 使用 `pnpm --filter tsuz-web-main dev` 启动应用，验证：未登录访问 `/apps` 和 `/profile` 会回到 `/login`；登录成功进入应用中心；顶部菜单可到个人中心并能退出；移动端宽度下管理员文字隐藏但图标可用；应用卡片显示完整且未接入的卡片给出提示；`/apps/mfe-app/*` 仍能显示 qiankun outlet/fallback。
3. 运行主应用 Playwright smoke 测试；若测试预期默认跳 `/apps/mfe-app` 与新的应用中心入口冲突，统一更新测试和登录默认路径，但保留远程子应用集成测试的 `/apps/mfe-app` 路径。
4. 最后检查 TypeScript 路由类型、Ant Design 控制台警告、导航刷新后的 SPA fallback，并确认没有从 `refer` 运行时导入代码或引入 Next 专属依赖。

# 需要在实施前确认的产品假设

本计划将“refer/app/page.tsx”解释为主应用的“应用中心”，推荐暴露为 `/apps`，同时让 `/` 兼容地指向应用中心；“`/apps/mfe-app/*`”继续保留给 qiankun 远程业务应用。登录页字段暂按现有 demo 认证的 `admin/password123` username 语义迁移，而不是擅自把认证协议改为邮箱。如果希望应用中心只使用 `/`，或希望所有八个卡片都直接挂载具体远程子应用，需要在实现时调整路由/配置而不是简单页面迁移。
